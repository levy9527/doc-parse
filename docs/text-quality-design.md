# 文本质量判定（水印噪声识别）— 设计与落地

> 关联实现：`src/docparse/text_quality.py`、`src/docparse/pdf_pipeline.py`（缺文字页判定）
> 关联决策：本文档**独立**说明"如何识别水印/无意义字符"，不并入 `ocr-design.md`。

## 1. 背景（真实问题）

部分招聘网站导出的 PDF（如微信/BOSS 模板简历），**页面可见内容其实是图片**，
但文字层里残留了水印：

- 一个长随机 token：`176ee020586f3dd11Hx53NW4EVtWxI6_UPuaWOGjmfXZMxhn3w~~`
- 一列竖排单字符：`f`/`~`/`w`/`3`/`n`/`h`…（每个字符一行）
- 页分隔：`---`

而 `docparse.pdf_pipeline.parse_pdf` 判断"某页要不要 OCR"的依据是**该页原生文字长度**，
于是这类页被水印撑到阈值（`PDF_TEXT_MIN_CHARS=300`）以上 → 被判为"有文字页" →
**跳过 OCR** → PDFMiner 只抽出水印 → 清洗后**内容为空**。

实测案例：`FDE- 郑露-北京.pdf` 每页原始 422/369/369/369 字，看似"文字充足"，
实际有效文字为 0；强制 OCR 后可读出 4811 字完整简历。

## 2. 目标与原则

1. **语言无关**：不能用"汉字占比"之类只适合中文的判据（英文简历会几乎无汉字）。
2. **保守优先**：宁可漏删噪声，不可误删正文——误删会直接改变"是否 OCR"的判定。
3. **只增不减**：新增判据不能让原本会 OCR 的页变成不 OCR（避免回归）。
4. **按行处理**：PDFMiner 把水印按独立行输出，行是天然且精确的处理粒度。

## 3. 噪声形态识别规则（`docparse.text_quality.strip_noise`）

核心思路：**不尝试"认出这是水印"，而是识别"正常文本不可能长这样"的形态**。

| 规则 | 正则/判据 | 命中对象 | 为什么安全 |
|---|---|---|---|
| A 长随机 token | `^[0-9A-Za-z_\-]{16,}[~^=+\-_.]{0,6}$` | 水印 token 行 | 正文几乎不存在"≥16 个连续不带空格/标点/CJK 的 ASCII 字符"；`https://`、`a@b.com` 含特殊符号不匹配；长单词（`TypeScript`）不到 16 |
| B 纯符号行 | `^[~^=+\-*\|_.·…:：,，、;；/\\ ]{1,8}$` | 分隔线、装饰符 | 整行无字母数字、无汉字，不携带语义 |
| C 竖排单字符 | 连续 **≥3** 行、每行恰为 1 个 ASCII 字符 | 竖排水印列 | 单个孤立字符**不删**（正文 `Java`/`C`/`Python` 会出现）；连续 3 个以上才是排版噪声 |

### 有效长度

```python
meaningful_length(text) = 剔除 A/B/C 后，逐行去掉空白字符的字符数之和
```

## 4. 缺文字页判定（`docparse.pdf_pipeline._page_needs_ocr`）

**双判据取"或"，只增不减：**

```python
if raw_len < THRESHOLD:                                   # 判据1：原有规则，完全不变
    return True
noise = raw_len - meaningful_len
if meaningful_len < THRESHOLD and noise >= raw_len * 0.5: # 判据2：新增
    return True
```

- 判据 1 保留原有语义，确保既有行为与测试不回归。
- 判据 2 精准命中"原始够长、但去掉噪声后所剩无几"的页，即**水印主导页**。
- `_WATERMARK_NOISE_RATIO = 0.5` 是安全阀：正常正文页噪声占比远低于 50%，
  不会被误伤；发现漏救（该 OCR 却未 OCR）时可下调。

### 为什么不用"替换式"判定

最初实现是"直接用去水印后的长度替换原长度"，结果 `demo.pdf` 第 5 页原始 338 字、
去噪后 285 字，**跌破 300 被误判为缺文字页** → 强行 OCR，破坏了其原本正确的行为
（`test_demo_is_text_pdf` / `test_parse_pdf_tier_a_matches_markitdown` 直接失败）。

正常文档的页字符数本就贴着阈值浮动，**任何字符损失都可能翻盘**。故改为"或 + 占比闸门"。

### 被否决的方案

| 方案 | 否决原因 |
|---|---|
| 用"汉字占比"判断 | 英文/中英混排简历几乎无汉字 → 会被全部误判为缺文字并强行 OCR |
| 见水印就 OCR | `邵康` 这类简历**同时含真文字与水印**，有效文字 1445 字，不该 OCR |
| 行内剥离（一行内既有正文又有水印） | 需字符级坐标聚类，复杂度高、风险大；当前按行整体保留（偏保守） |

## 5. 实测区分度（真实文件）

| 文件 | 原始长度 | 有效长度 | 噪声占比 | 判定 |
|---|---|---|---|---|
| 郑露（内容在图片里） | 422 | 0 | ~100% | ✅ 走 OCR |
| 邵康（真文字 + 有水印） | 2014 | 1445 | 28% | ❌ 用真文字，不 OCR |
| demo.pdf 第 5 页 | 338 | 285 | 16% | ❌ 判定不变（原行为） |

> 注意邵康同样带竖排水印，但因有效文字充足而被正确判定为"有文字页"——
> 这正是"分成两类"而非"见水印即 OCR"的价值。

## 6. 测试（`tests/test_text_quality.py`）

- 水印样本 → `meaningful_length` 接近 0；`strip_noise` 全剔除。
- 正常中英文正文**不被削减**（`communicate effectively with stakeholders` 完整保留）。
- 长单词（<16）不被误判为 token。
- 孤立单字符保留、连续段删除。
- 判定边界：`(422, 8) → True`、`(338, 285) → False`、`(250, 240) → True`（原规则不变）。

全量套件：`25 passed`（原 17 个全绿，无回归）。

## 7. 配置

| 参数 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `PDF_TEXT_MIN_CHARS` | `src/docparse/config.py`（环境变量） | 300 | "缺文字"的绝对门槛 |
| `_WATERMARK_NOISE_RATIO` | `src/docparse/pdf_pipeline.py` 常量 | 0.5 | 噪声占比闸门 |

## 8. 已知限制 / 待改进

1. **中文水印**（CJK 竖排）：规则 C 只认 ASCII 单字符，不生效。
2. **水印与正文同行**：行级规则无法拆分，整体保留（偏保守，不误删）。
3. **正文中的长随机串**（长订单号/哈希）会被规则 A 删除，影响仅为少算少量字符，
   且有 50% 闸门兜底。
4. **两处清洗规则尚未统一**：本模块（判定用，保守）与
   resume-funnel `textclean`（给人看的正文清洗，稍激进：连排 ≥4、token 仅认 `~` 结尾）
   目的不同、阈值不一致，后续可考虑合并到一处。
5. `_WATERMARK_NOISE_RATIO` 建议后续也做成环境变量，便于按实际语料调参。
